# Schema.json Structure Specification

> **IMPORTANT FOR CLAUDE CODE**: This is the official reference specification for `schema.json` files.
> When generating or modifying schema files, you MUST follow this structure exactly.
> The `analyze_database.py` script generates schema files according to this specification.

This document defines the structure for `schema.json` files generated by database analysis. Use this as a reference when generating schema documentation for any PostgreSQL database.

## Root Structure

```json
{
  "database": "string",
  "schema": "string",
  "description": "string",
  "tables": [],
  "relationships": [],
  "commonQueries": []
}
```

### Root Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `database` | string | Yes | Name of the database |
| `schema` | string | Yes | Schema name (usually "public" for PostgreSQL) |
| `description` | string | Yes | Human-readable description with generation timestamp |
| `tables` | array | Yes | Array of table objects |
| `relationships` | array | Yes | Array of relationship objects (foreign key relationships) |
| `commonQueries` | array | No | Array of useful pre-built queries for the database |

---

## Table Object Structure

```json
{
  "name": "table_name",
  "fullName": "schema.table_name",
  "rowCount": 1000,
  "description": "Human-readable description of what this table stores",
  "columns": []
}
```

### Table Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Table name |
| `fullName` | string | Yes | Fully qualified name (schema.table) |
| `rowCount` | number | Yes | Current row count in the table |
| `description` | string | Yes | Human-readable description of the table's purpose |
| `columns` | array | Yes | Array of column objects |

---

## Column Object Structure

### Basic Column (Required Fields)

```json
{
  "name": "column_name",
  "type": "TYPE",
  "nullable": true,
  "description": "Human-readable description"
}
```

### Column with Primary Key

```json
{
  "name": "id",
  "type": "NUMBER",
  "nullable": false,
  "description": "Primary key for this table",
  "isPrimaryKey": true,
  "statistics": {
    "distinct": 1000,
    "min": 1.0,
    "max": 1000.0
  },
  "cardinality": "unique"
}
```

### Column with Foreign Key

```json
{
  "name": "other_table_id",
  "type": "NUMBER",
  "nullable": false,
  "description": "Foreign key to other_table",
  "isForeignKey": true,
  "references": {
    "table": "other_table",
    "column": "id"
  },
  "statistics": {
    "distinct": 500,
    "min": 1.0,
    "max": 500.0
  },
  "cardinality": "high"
}
```

### Column with Sample Values (Low Cardinality)

```json
{
  "name": "status",
  "type": "TEXT",
  "nullable": true,
  "description": "Current status",
  "statistics": {
    "distinct": 5
  },
  "cardinality": "low",
  "sampleValues": ["pending", "processing", "shipped", "delivered", "cancelled"]
}
```

### Column Fields Reference

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | string | Yes | Column name |
| `type` | string | Yes | Standardized data type (see Data Types below) |
| `nullable` | boolean | Yes | Whether NULL values are allowed |
| `description` | string | Yes | Human-readable description of the column |
| `isPrimaryKey` | boolean | No | Set to `true` if this is a primary key column |
| `isForeignKey` | boolean | No | Set to `true` if this is a foreign key column |
| `references` | object | Conditional | Required if `isForeignKey: true` |
| `references.table` | string | Conditional | Referenced table name |
| `references.column` | string | Conditional | Referenced column name |
| `statistics` | object | No | Statistical information about the column data |
| `statistics.distinct` | number | No | Count of distinct values |
| `statistics.min` | number | No | Minimum value (numeric/timestamp columns) |
| `statistics.max` | number | No | Maximum value (numeric/timestamp columns) |
| `cardinality` | string | No | Cardinality level (see Cardinality Rules below) |
| `sampleValues` | array | Conditional | Sample values for low/medium cardinality columns |

---

## Standardized Data Types

Map PostgreSQL types to these standardized types:

| Standard Type | PostgreSQL Types |
|--------------|------------------|
| `NUMBER` | integer, bigint, smallint, serial, bigserial, numeric, decimal, real, double precision, float |
| `TEXT` | varchar, character varying, char, character, text, uuid |
| `BOOLEAN` | boolean, bool |
| `TIMESTAMP` | timestamp, timestamptz, date, time, timetz |
| `JSON` | json, jsonb |
| `BINARY` | bytea |
| `ARRAY` | any array type (e.g., text[], integer[]) |

---

## Cardinality Rules

Cardinality is determined by the ratio of distinct values to total rows:

| Cardinality | Condition | Include Sample Values? |
|-------------|-----------|------------------------|
| `unique` | distinct == rowCount OR isPrimaryKey | No |
| `low` | distinct/rowCount <= 0.05 (5% or less) | Yes (up to 20 values) |
| `medium` | distinct/rowCount <= 0.25 (5-25%) | Optional (if < 50 values) |
| `high` | distinct/rowCount > 0.25 (> 25%) | No |

## Relationship Object Structure

```json
{
  "from": "child_table",
  "to": "parent_table",
  "type": "many-to-one",
  "keys": ["foreign_key_column", "referenced_column"]
}
```

### Relationship Fields

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `from` | string | Yes | Table containing the foreign key |
| `to` | string | Yes | Referenced/parent table |
| `type` | string | Yes | Relationship type (usually "many-to-one" for FK) |
| `keys` | array | Yes | Two-element array: [FK column, referenced column] |

---

## Common Queries Object Structure

```json
{
  "description": "Short description of what the query does",
  "query": "SELECT ... FROM ... ;"
}
```

Include useful queries like:
- Aggregate summaries (totals, counts)
- Time-based analysis (by month, year)
- Top N queries (best sellers, top customers)
- Status breakdowns
- Join queries showing relationships between tables

## Description Writing Guidelines

### Table Descriptions
- Start with what the table stores (e.g., "Customer shipping and billing addresses")
- Keep it concise but informative
- Mention key relationships if relevant

### Column Descriptions
Common patterns:
- Primary keys: "Primary key for [entity]"
- Foreign keys: "Foreign key to [table]" or "[Entity] that [relationship]"
- Timestamps: "Timestamp when [event]" (created_at, updated_at, etc.)
- Booleans: "Whether [condition]"
- Status fields: "Current [entity] status"
- Amounts: "Total [what] including [details]"

### Generating Meaningful Descriptions
Based on column name patterns:
- `*_id` → Primary/Foreign key
- `*_at` → Timestamp
- `is_*` / `has_*` → Boolean flag
- `*_count` / `*_quantity` → Numeric count
- `*_amount` / `*_price` / `*_fee` → Monetary value
- `*_url` / `*_link` → URL reference
- `email` → Email address
- `phone` → Contact phone number
- `name` / `first_name` / `last_name` → Name fields
- `status` → Status indicator
- `type` → Type/category indicator

---

## Usage Notes

1. **Always include statistics** for numeric columns (min, max, distinct)
2. **Always include sample values** for low cardinality text/timestamp columns
3. **Generate meaningful descriptions** - don't just repeat the column name
4. **Include all foreign key relationships** in the relationships array
5. **Add common queries** that would be useful for analyzing the data
6. **Use ISO timestamp format** for the generation timestamp in description
